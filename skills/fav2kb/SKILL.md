# 抖音收藏 → 知识库

用户只负责一件事：刷到有用的抖音，放进对应的收藏夹（收藏夹即主题）。**知识库放在哪、存成什么样、要不要提炼、怎么提炼，都由用户决定**：你负责问清楚、说明代价、记录下来，之后照做。

只有用户选定的收藏夹会被同步。只点收藏、没放进收藏夹的作品不会同步；用户问起时，提醒用户放进对应的收藏夹。

分工：
- `fav2kb` 命令负责确定性工作：登录采集、下载、转写，产出**原始素材**。素材只增不改。
- 你负责和用户沟通，并按用户偏好把素材**提炼**成笔记。提炼要消耗用户的模型用量，所以规模大时必须先征得同意。

## 0. 检查安装

```bash
fav2kb --help
```

命令不存在时，先征得用户同意再安装（需要 [uv](https://docs.astral.sh/uv/)）：

```bash
uv tool install "fav2kb[asr] @ git+https://github.com/a915578105/fav2kb"
fav2kb setup
```

用户不需要视频转写时，去掉 `[asr]`。`setup` 会下载浏览器内核；加 `--asr` 时还会下载约 230MB 的转写模型。

## 1. 首次配置：逐项询问用户

先运行 `fav2kb pending`：提示"还没有知识库"就进入首次配置；能列出内容就跳到第 3 步。

**一次问一个问题，给出推荐选项和代价，不要替用户猜。** 问之前，先看看用户当前项目里有没有现成的知识库目录（例如 `docs/`、`notes/`、Obsidian vault）。

1. **知识库放在哪？** 可以是当前项目里的某个目录、已有的 Obsidian vault，或一个新目录。
2. **同步哪些收藏夹？** 运行 `fav2kb folders` 列给用户看。首次运行会弹出浏览器窗口，**提醒用户用抖音 App 扫码**。用户可以选全部，也可以只选部分。
3. **视频要不要转写成文字？** 推荐要，否则只能看到作者写的文案。转写在本地完成，不上传，约 10 秒处理一条 1～3 分钟的视频，首次需要下载约 230MB 模型。
   转写后要不要保留音频？保留时每分钟约占 0.4～1.4MB 磁盘；agent 一般用不上音频，磁盘紧张就选删除（`--no-audio`）。
4. **提炼到什么程度？** 可以每个收藏夹分别设置。先把代价说清楚：

   | 方式 | 产出 | 代价 | 适合 |
   |---|---|---|---|
   | 不提炼 | 只有原始素材，用到时你直接查素材 | 无额外消耗 | 收藏量大、只想留档 |
   | 一行摘要 | 每条一行摘要 + 标签，汇总在一个索引页 | 低：每条读一遍素材，写几十字 | 随手收藏、需要快速浏览 |
   | 每条一篇笔记 | 摘要 + 要点 + 标签 | 中：每条读一遍素材，写几百字 | 观点、经验、灵感类 |
   | 按主题合并 | 新知识并入主题页（如"胸肌训练""家常菜"） | 中偏高：还要读已有的主题页再合并 | 教程、菜谱、可积累的技能 |

5. **什么时候提炼？**
   - 同步后立即提炼。
   - 用到时再提炼：平时只同步素材，等用户问到相关问题时，只提炼用到的条目。收藏量大时推荐这种。
6. **笔记格式和组织方式？** 普通 Markdown、Obsidian（双链 `[[ ]]`、标签、frontmatter），或沿用已有格式。如果已有知识库，先读几篇现有笔记，照它的风格写。还要问清按收藏夹、按主题还是平铺来分目录。
7. **提炼时特别要保留什么？** 例如训练动作的组数次数、菜谱的用量和步骤、原话金句、图片里的表格。另外问清笔记用什么语言、写多详细。
8. **背景音乐里的歌词怎么处理？** 转写会把背景音乐的歌词也识别出来。默认排除，不写进笔记；如果知识库本来就是收集台词、歌词的，选保留。
9. **依赖画面的视频怎么处理？** 有些视频的信息主要在画面里（动作示范、软件操作、成品展示），只看转写会丢信息。可选：
   - 照常提炼，在笔记里标注"需看画面"，并汇总到一个待回看清单（推荐）；
   - 只记标题、文案和链接，放进待回看清单；
   - 跳过。
10. **单次自动提炼的上限？** 一次待提炼的条目超过多少时要先问用户。默认是 30 条或约 10 万 token，超过就停下来问。
11. **要不要让其他 agent 知道这个知识库？** 用户同意后，在项目的 `AGENTS.md` / `CLAUDE.md` 里加一行指引。

问完后执行：

```bash
fav2kb init --kb "<知识库目录>" --folders <收藏夹 id> ... [--asr] [--no-audio]
# 全部收藏夹用 --all 代替 --folders
```

`--folders` 用 `folders` 列出的 id，不用名称，因为抖音允许收藏夹重名。

然后把用户的回答写进 `<知识库>/_fav2kb/preferences.md`。之后每次提炼前都先读这个文件：

```markdown
# 抖音收藏整理偏好
| 收藏夹 | 提炼方式 | 时机 | 笔记位置 |
|---|---|---|---|
| 健身 (7176…) | 每条一篇笔记 | 同步后立即 | 笔记/健身/ |
| 饭 (7354…) | 按主题合并（一道菜一页） | 同步后立即 | 笔记/菜谱/ |
| 其余 | 一行摘要 | 用到时再提炼 | 笔记/收藏索引.md |
- 格式：Obsidian，frontmatter 含 tags/source/author/aweme_id，正文用双链关联主题
- 必须保留：训练动作的组数次数；菜谱的用量与步骤
- 语言与详略：中文，摘要 3 句以内，要点不超过 7 条
- 背景音乐歌词：排除
- 依赖画面的视频：照常提炼并标注"需看画面"，汇总到 笔记/待回看.md
- 自动提炼上限：30 条或约 10 万 token，超过先问
```

**第一次提炼时，先试做 3 条给用户看**，确认风格和详略后再继续；用户的修改意见要写回 `preferences.md`。

## 2. 知识存放约定

- **原始素材**在 `<知识库>/_fav2kb/`，由命令维护，不要修改。用户在抖音取消收藏后，素材也不会删除。每条素材的 `README.md` 包含元信息、作者文案、文章正文，以及带 `[分:秒]` 时间戳的转写；`images/` 里是全部图片。
- **命令对转写做的初筛**（结果在 `pending --json` 的字段和 README 的提示行里）：
  - `transcript_quality`：`ok`；`low` 表示有效字数很少；`none` 表示没有人声。
  - `lyric_lines`：被标成 `〔疑似歌词/杂音〕` 的行数。只能识别外语歌词和重复的副歌，中文歌词要靠你读的时候判断。
  - `visual_dependency`：`high` 表示信息主要在画面（口播很少）；`medium` 表示讲解多次指向画面；`low` 表示看文字基本够。
  这些都是粗筛，读素材时以你的判断为准。
- **一个作品只写一篇笔记**。它属于多个收藏夹时，在 frontmatter 里全部列出。同名收藏夹用 `pending --json` 里的 `folder_ids` 区分。
- **每篇笔记都要可溯源**：frontmatter 带原链接、作者、aweme_id，并用相对链接指向素材 `README.md`。
- **维护笔记索引**：每篇笔记在索引里占一行；按主题合并时，主题页末尾列出用到的来源条目。不要只依赖素材里的 `_fav2kb/INDEX.md`，那是素材清单，不是笔记索引。

## 3. 同步与提炼

用户说"同步一下抖音收藏"或类似的话时：

```bash
fav2kb sync
fav2kb stats --json
```

首次导入上百条时，用 `fav2kb sync --limit 50` 分批同步，可以放到后台反复运行。每次都会重新拉列表拿新直链，并跳过已同步的条目，直到不再提示"留到下次 sync"为止。

根据 `stats` 结果和 `preferences.md` 决定下一步：
- **没有待提炼的条目，或偏好是"用到时再提炼"**：只汇报新增了多少条，不提炼。
- **待提炼的量不超过上限**：按偏好直接提炼。
- **超过上限：停下，先向用户说明代价，由用户决定。** 说明里要包括：
  - 多少条，按收藏夹和类型分别是多少（`by_folder`、`by_type`）；
  - 要读入多少：文本约 `est_text_tokens`，图片 `images` 张（约 `est_image_tokens`），每篇笔记还要输出几百 token；
  - 对用户意味着什么：按量付费的 API 用 token 数乘单价估算；订阅制会消耗用量额度，可能触发限额；还要说明大致耗时；
  - 其中有 `low_quality_transcripts` 条转写内容很少，提炼价值低，建议跳过；
  - 有 `lyric_suspects` 条含疑似歌词，`visual_high` / `visual_medium` 条依赖画面，只看文字会丢信息；
  - 可选方案：全部提炼、只提炼某些收藏夹、只提炼最近 N 条、先试 3 条、降为一行摘要、改为用到时再提炼、暂不提炼。

  用户的选择如果是长期规则，写回 `preferences.md`。

`preferences.md` 里还没定歌词或依赖画面的处理方式，而这次正好遇到时，先把这些条目列给用户看（标题，加一两行疑似歌词或"口播很少"的说明）：疑似歌词的转写很短，读一遍几乎不花费用量。请用户决定后写回偏好。

提炼时分批进行，每批不超过 20 条：

```bash
fav2kb pending --json --limit 20
```

对每一条：
1. 读 `preferences.md` 中对应收藏夹的设置，再读这条素材的 `README.md`。如果你能看图片，图文条目要看 `images/`，很多知识在图里。
2. 按偏好写笔记，并更新笔记索引。
3. 写完一批后标记：`fav2kb done <aweme_id> ...`，再取下一批。中途被打断也不会丢进度。
4. 不写笔记的条目也要标记，并写明原因：`fav2kb done <aweme_id> --skip "纯音乐，无口播"`。原因会显示在素材索引里，方便用户以后回看。

提炼规则：
- **只写素材里有的内容**，不要补充视频里没说的东西。转写里明显的同音错字可以按上下文纠正；拿不准的地方标"（转写存疑）"。
- **转写标了"内容很少"的视频**（`transcript_quality` 为 `low` 或 `none`）多半以背景音乐或画面演示为主，不要从零碎的转写里硬编内容。如果标题和文案里有实质信息（比如动作名称、组数），可以只根据文案写一篇短笔记并注明"仅根据文案"；否则用 `--skip` 跳过，并提醒用户这类视频需要回抖音看画面。fav2kb 暂不识别画面字幕，因为逐帧识图的成本太高。
- **歌词**：偏好是排除时，忽略 `〔疑似歌词/杂音〕` 行；没被标出、但明显是歌词的行（押韵、抒情、和视频主题无关）也一样忽略。整条转写都是歌词时，按"内容很少"处理。偏好是保留时，把歌词单独放在"歌词/台词"一节，不要混进知识要点。
- **依赖画面**：`visual_dependency` 为 `high` / `medium`，或你读的时候发现关键步骤只说了"这样""这里"而没有描述时，按偏好处理。照常提炼的，在笔记开头标"👁 需看画面"，写清楚哪部分要看（带转写里的 `[分:秒]` 时间点）和原链接，并把这条加入待回看清单。
- 收藏内容和收藏夹主题不符时照常整理，在汇报里提一句即可。
- 选按主题合并时，先找已有的主题页再合并，不要重复建页。

最后向用户汇报：新增几条、提炼了几条、跳过了几条（附原因）、排除了几条的歌词、几条依赖画面（已加入待回看清单）、写到了哪里；`sync` 末尾列出的"媒体不完整"条目连同原因一起说明。

## 4. 用到时再提炼

用户问到可能和收藏有关的问题时（例如"我收藏的卧推要点是什么"），先查已有笔记，再用 `rg` 搜 `<知识库>/_fav2kb/items/*/README.md`，读相关条目后回答，并给出原链接。如果偏好是"用到时再提炼"，把这次用到的条目按偏好写成笔记，再 `done`。

## 5. 修改偏好

用户想换提炼方式、时机或格式时，修改 `preferences.md`；想换收藏夹、开关转写、改音频保留时，重新运行 `init`。之后都按新偏好执行。不要擅自重写已经提炼过的旧笔记，除非用户要求。

## 6. 故障处理

- **需要扫码**：登录失效时 `sync` / `folders` 会弹出浏览器，请用户扫码。
- **安全验证**："没拿到收藏夹列表"时，加 `--headed` 重试，请用户在浏览器里手动完成验证。**不要尝试绕过验证。**
- **浏览器启动失败**：可能有另一个 fav2kb 正在运行，等它结束后再试。
- **媒体不完整**：多为直链过期（HTTP 403）或作品已删除。下次 `sync` 会用新直链自动重试，不要手动下载。
- **转写依赖缺失**：按提示用 `fav2kb[asr]` 重新安装。

## 7. 不要做的事

- 不要读取、复制或展示 `~/.fav2kb/browser/`，它里面是登录 Cookie。
- 不要访问用户以外的账号，也不要批量抓取别人的主页。
- 没有实际成功的事不要说成功。例如用户要求定时同步时，只有真正创建并验证了任务，才能说已启用。
- 素材和笔记仅供用户个人学习，不要替用户公开发布原作者的内容。
